## Performance implementation and tradeoffs

The initial unoptimized adapter repeats full decode and validation before and after an atomic fake update. Its measured checkpoint execution median/p95/peak was 186.866/211.780/224.884ms, versus 98.295/102.679/105.499ms for the legacy fake adapter in the same probe. These are synchronous fake processing costs, not DataStore latency. Compact representation alone made processing slower.

Two narrow changes are implemented: avoid copying discarded lease projection subtrees; and preserve deeply immutable values internally in the compact fake adapter. The latter enables a bounded decoder proof keyed by immutable envelope identity, owner and scalar encoder identity. A new envelope must first reconstruct all history and pass complete authoritative validation before a proof is recorded. Every cache access still runs bounded canonical traversal. Returned live fields are independent mutable copies; only the recursively frozen legacy audit branch may be shared. This preserves baseline validation proofs across processing without exposing writable historical evidence. No string hash or mutable identity authorizes a hit. Legacy fake adapter default copy semantics remain unchanged. Retention is capped at 16 records and 4MiB of encoded-equivalent input/output payload; actual tables, metadata and allocator overhead are additional. Eviction affects speed only. No real adapter changes.

A canonical profile still must pass the original 256KiB decoded-profile limit as well as the physical compact limit. Compact headroom does not implicitly authorize a larger national fleet; changing that validation contract requires later review.
