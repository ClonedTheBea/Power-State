## Existing integration and minimum change

The normal Test boot starts independent P2a/P2b previews and mounts P2b. Schema3 fake construction is started by the automatic test runner and mounted separately. Its existing ProfileService, quote service, demand/billing loop, atomic Build and bounded fake store already implement most gameplay. ConstructionClient currently replaces all inspectors with district information and lacks generator control.

Use ConstructionTestService as the single normal Test host and ConstructionClient as its GUI. Retain legacy preview hosts only when the explicit RunRegressionTests attribute is true. Automatic test runners also require that flag; test.project.json defaults it false. Production universe and default mapping remain unable to activate this Test path. No additional adapter selection or real service route is introduced.

Reuse the existing validated IntentHandler on a copied state for generator control, then replace its single-sink report with the approved district solver report before installing/staging the candidate. Reject control while the profile cannot mutate. Keep generator and construction command sequences separate and tied to the current server command epoch.

Keep the bounded four-marker Native map with prospective district slot. Distinguish the preview feeder from committed energized infrastructure. Contextual inspectors expose generator control, substation capacity, customer delivery and the district review. Reuse shared navigation, modal, focus, 44px targets and Bank formatting; group financial totals and use completed-project wording. Opening panels never pauses simulation.

Fake storage survives disconnect/reconnect only while the same server is running. Display that Stop Play discards saves. Loading/failure and live/confirmed financial state remain distinct. The server-only regression interface may simulate departure/rejoin and inject fake faults; it is never a client remote or real adapter.
